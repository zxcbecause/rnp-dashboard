## Руководитель финансового отдела

Метрики «уже действуют» (всё — ручной ввод, Э1):

| Метрика | unit / direction |
|---|---|
| Скорость закрытия отчётного периода (раб. дни на закрытие месяца/квартала) | days / lower, помесячно |
| Своевременность управленческой отчётности (% отчётов в срок) | percent (formula: в срок / всего) / higher |
| Экономия / оптимизация затрат (эффект инициатив) | eur / higher |
| Ошибки в отчётности (корректировки после сдачи) | count / lower |
| Соблюдение сроков налоговой/бухгалтерской отчётности | boolean или percent / higher |
| Контроль дебиторской/кредиторской задолженности (цикл оборота, кассовый разрыв) | **неоднозначно** — нужна формула (дни оборота? сумма просроченной ДЗ?) |
| Соблюдение платёжного календаря (% платежей по графику) | percent (formula) / higher |
| Текучесть кадров в отделе (% увольнений) | percent (formula) / lower |
| Вовлечённость / удовлетворённость (опросы) | балл — **нужна шкала** |
| Автоматизация процессов (доля переведённых процессов) | percent / higher |
| SLA по запросам других отделов | percent или часы — **нужна формула** |
| Bus factor (критичные процессы, которые умеет только один человек) | count / lower |

Бюджетирование вводится поэтапно (Этап 0 — подготовка, текущий; 1 — запуск; 2 — стабилизация; 3 — зрелый процесс).
Метрики этапа 0: регламент утверждён (boolean), готовность бюджетных форм (% от плана), соблюдение сроков
разработки методологии. Метрики следующих этапов включаются по решению (в модели: `is_active` + заметка в карточке).

Взаимозаменяемость (матрица компетенций «сотрудники × процессы» 0–3, основной/дублёр, план замещения,
ротация, ежеквартальная практика дублёра) — **отдельный модуль, в модели его нет**. Bus factor считается из матрицы.

## Финансовый отдел: регулярные действия («метрики отдела .pages»)

Списки «Приход» и «Расход» — это не числовые метрики, а **базовые функции** (регулярные действия с отметкой
выполнения → Execution rate). Например:

- Приход: ежедневная работа с приходом; возврат депозитов на вторые сутки после выезда; обработка запросов в Битрикс
  в течение суток; еженедельная сверка авансовых платежей; ежемесячная сверка мануальных бронирований на комиссию;
  ликвидации в срок; фактуры до 20 числа следующего месяца; ежемесячные перерасчёты с La Vida; еженедельная сверка
  наличных в офисах; контроль диспутов; данные для юристов и налоговой.
- Расход: ежедневный контроль расходов и фактур; еженедельный учёт подрядчиков; статья расхода и ответственный у
  каждой операции; ведение Acme Invest; ответ по сметам в течение суток; запросы Битрикс в течение суток; ликвидации
  в срок; фактуры до 20 числа; данные для юристов и налоговой.

Нужно в модели: периодичность `quarterly` (добавлена), **срок внутри периода** («до 20 числа», «в течение суток») —
пока только текстом в названии; привязка базовой функции не только к метрике, но и к **отделу/направлению**
(сейчас `base_function.metric_id` обязателен).
